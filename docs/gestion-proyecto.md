# Gestión de Proyecto y Metodología

Para el desarrollo del sistema **Descalifica2**, el equipo optó por una metodología de trabajo colaborativa e iterativa. La dinámica consistía en determinar en conjunto las tareas a realizar y asignarlas de manera equitativa. Durante el desarrollo, manteníamos una comunicación constante para consultar sobre cualquier bloqueo técnico que pudiera surgir. La integración de los cambios se gestionó mediante Pull Requests, lo que nos permitió establecer un proceso estricto de revisión de código para asegurar la calidad antes de fusionar cualquier funcionalidad.
Además de este flujo asíncrono, llevábamos a cabo reuniones eventuales. Estos encuentros tenían como objetivo principal diagramar los pasos a seguir, realizar un balance de las etapas anteriores, exponer el código y las funcionalidades desarrolladas, y debatir en equipo las mejores soluciones para los desafíos del proyecto.

### Flujo de un Issue
 Un integrante crea el issue con su nombre y descripción -> el mismo u otro integrante se lo asigna -> Crea una rama nueva y desarrolla la solución -> Crea una Pull request con una descripción de la solución. -> otro integrante lo revisa y cierra la PR mergeando la branch. -> el issue se pasa a Hecho.
